# Exact preflop equity table

This directory holds `equity_table.json`, the pre-computed exact preflop equity
table (hero hand vs opponent hand, 169 × 169 canonical pairs). It is generated
once via exhaustive board enumeration and then read at runtime by
`AggregateEquity` for instant, reproducible range equity (no variance, no
seed).

## Generating the table

The table is generated by enumerating every 5-card runout (C(48,5) = 1 712 304
boards per disjoint combo-pair) with the fast `phevaluator` adapter, and
**averaging over every disjoint combo-pair** of each canonical pairing.

Averaging over all disjoint combo-pairs is required for exactness: suit
symmetry does **not** hold in general. When a combo-pair shares a rank between
hero and opponent (e.g. AKo vs AKo, AKo vs AQo, AA vs AKs), the card-removal
effect of the shared rank depends on the exact suits dealt, so different
combo-pairs of the same canonical pairing can yield different equities. Only
the average over all disjoint combo-pairs is the exact equity of the pairing.

```bash
cd backend
# Full table (~28 561 entries; a few hours on a multi-core machine, resumable).
python -m poker_tool.scripts.generate_equity_table --resume

# Small sample (for a sanity check).
python -m poker_tool.scripts.generate_equity_table --limit 24 --workers 4
```

The script writes incrementally and checkpoints after every batch, so an
interrupted run can be resumed with `--resume` (already-computed entries are
skipped).

Once generated, `equity_table.json` is committed to this directory so the
exact equity is available to everyone without re-running the computation.

> Note: pairings sharing a rank enumerate several disjoint combo-pairs (up to
> a few hundred), so the full generation is slower than a single-combo run.
> The result is exact and reproducible, which is the trade-off for the extra
> enumeration.
